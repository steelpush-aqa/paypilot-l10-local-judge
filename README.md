# L10 — суддя критерію ескалації всередині периметра

Перекалібрування судді L09 (LLM-as-judge для критерію ескалації PayPilot) з хмарної
моделі на локальну, щоб виклик моделі не виходив за периметр даних. Той самий
зафіксований набір і та сама рубрика, що в L09, змінено лише модель судді.

## Рішення

```
еталон (хмара):   claude-haiku-4-5    узгодженість 0,97 (0,83–0,99)
кандидат (локально): qwen3.5:9b        узгодженість 0,80 (0,63–0,90)
```

Інтервали Вілсона перекриваються, тому за цим набором судді не розрізняються за
середнім. Рішення ухвалено за розподілом промахів: локальний суддя шумніший і
занадто суворий на непрямому називанні людини, але його помилки переважно хибні
тривоги (безпечний для ескалації бік), і виклик більше не виходить за периметр.
**Вердикт: переїжджати з умовою** (мажоритарне голосування з 5 прогонів, суддя
лишається на release gate, тег+дайджест закріплено). Повна аргументація -
`model-selection-recommendation.md`.

## Відтворити калібрування (chain-ready)

Команда запускається в середовищі курсу (eval-харнес L10 поруч зі стендом) і пише
`reports/calibration-l09_labels-*.json` із заповненим полем `judge_model`. L13 бере
суддю за цією конфігурацією: та сама модель і той самий режим виклику з `judge.local.env`.

```
JUDGE_MODEL=ollama:qwen3.5:9b docker compose run --rm --entrypoint python eval tools/calibrate_run.py l09_labels
```

Порівняти з хмарним суддею за правилом інтервалів:
```
python3 tools/compare_judges.py evals/reports/calibration-l09_labels-20261115T081031.json evals/reports/<новий звіт>.json
```

## Безпека

`.env` і будь-які ключі в репозиторій не потрапляють (див. `.gitignore`). Звіти в
`evals/reports/` містять синтетичні дані стенду (фіктивний банк Verta), не реальних клієнтів.
